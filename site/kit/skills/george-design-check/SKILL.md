# Design check

The second pair of eyes. It reviews; it doesn't build.

## Hard checks (any one fails the review)

1. Colors and fonts come from the page's tokens (DESIGN.md), not one-off values.
2. Nothing invented: no fake metrics, testimonials, logo walls or "trusted by" counts.
3. The headline, one sentence and the main action are visible without scrolling on a 1280 by 800 screen and readable at phone width.
4. Every button and link shows a visible focus state for keyboard users.
5. No purple-to-blue gradients, cards inside cards, emoji used as icons, or drawn browser windows.
6. No tiny all-caps "eyebrow" labels above every heading.
7. Text over images stays readable (contrast AA).
8. Scripture and key text are real text; every meaningful image has alt text.
9. Motion respects reduced-motion settings; nothing important depends on animation.
10. About 80 words or fewer on any one screen of the hero.

## Taste checks (fix or explain)

- Does it look like this person and this ministry, or like any template? Name one thing only George's page has.
- Real photos of real people and places, used large and cropped with intent.
- Type with character and a clear size hierarchy; no more than two typefaces.
- Generous, consistent spacing; a capped content width that doesn't stretch on big screens.
- One accent color used sparingly.

## Steps

1. Open the draft at phone width and at laptop width. Take screenshots of each section.
2. Run the hard checks; list each failure with the section and a specific fix.
3. Run the taste checks; list the top three improvements.
4. Verdict: PASS, FIX (list), or REDO (the direction is wrong).
5. Attach the report to the dashboard item.

## Rules

- Review someone else's build, or your own only in a fresh session with the screenshots, not from memory.
- No em dashes in the report.
